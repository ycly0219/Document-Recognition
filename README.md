# GE单据批量OCR处理工具

基于 Tkinter 的单文件桌面工具，用于批量选择 GE 单据图片/PDF，调用内部 OCR 服务识别，按单据规则拆分明细，导出 Excel，并将本次批量统计写入飞书多维表格。

## 当前功能

- 支持三种单据模板：`GE-ORACLE拣货单`、`GE-OSCAR拣货单`、`GE-发票单`
- 批量选择 `png`、`jpg`、`jpeg`、`pdf` 文件
- 上传文件到内部文件服务，提交异步 OCR 任务并轮询结果
- 按单据类型解析头部字段和明细字段
- 发票明细支持按 LPN/Serial 与数量关系拆分
- 解析完成后进入可编辑预览表格，可双击单元格修改、新增行/删除行
- 解析成功返回预览时即写入飞书统计；人工点击「确认并导出」后才生成 Excel（识别结果列表 + 全量处理日志），导出成功后保留数据可再次导出
- 新增「模拟数据」勾选框，不调用真实接口即可演示预览、编辑、导出流程
- 批量统计写入飞书多维表格
- 批量处理在后台线程执行，通过消息队列刷新界面日志，不会长时间冻结窗口
- 日志统一走标准 `logging`，不再覆盖标准输出

## 运行环境

- Python 3
- Tkinter（Python 标准库自带）
- `requests`
- `openpyxl`
- 能访问内部 OCR、文件服务和飞书 API 的网络环境

## 安装与运行

```bash
python3 -m pip install requests openpyxl
python3 "tool(1).py"
```

## 使用步骤

1. 选择单据模板。
2. 点击“选择文件并开始处理”。
3. 多选需要处理的图片或 PDF。
4. 等待处理完成，界面日志会展示上传、OCR 提交、轮询和解析进度。
5. 处理完成后，界面显示可编辑预览表格，双击单元格修改内容，或用「新增行 / 删除行」调整明细。
6. 核对无误后点击「确认并导出」，Excel 文件写入当前工作目录并同步飞书统计。
7. 点击「清空/重新开始」丢弃当前已核对数据，回到初始状态重新处理。

## 输出文件

导出文件名为：

```text
GE单据OCR识别结果_YYYYMMDD_HHMMSS.xlsx
```

其中包含两个 Sheet：

- `识别结果列表`：每个明细生成一行；发票明细会按 LPN/Serial 与数量关系拆分。
- `全量处理日志`：记录文件名、`fileId`、文件 URL、`reqUuid`、状态和异常信息。其中“提取单据编号”和“识别报文”字段当前为预留空列。

## 配置说明

当前配置集中在 `tool(1).py` 顶部的“配置区域”：

- OCR 接口地址、上传接口、结果查询接口
- OCR App 凭据、组织号、模板对应的 `modelId`
- OCR 轮询次数 `OCR_MAX_RETRY`、轮询间隔 `OCR_RETRY_INTERVAL`
- 飞书 App 凭据、多维表格记录写入地址

当前项目仅内部使用，采用硬编码方式管理以上配置。所有地址、密钥、模型 ID、字段名和解析规则都写在代码中，不迁移至外部环境变量或者配置文件中。

## 已知问题与改进建议

- OCR 轮询参数已提取为常量，批量处理已放到后台线程；若业务需要，可继续增加取消按钮或超时配置。
- 日志已统一改为标准 `logging`，GUI 日志通过队列由主线程刷新。
- 空的 `HEADERS` 已移除；如上传接口后续要求鉴权，请按接口要求补充请求头。
- Excel 输出目录使用 `os.getcwd()`，从快捷方式或不同目录启动时输出位置不稳定，建议固定到脚本目录或由用户选择目录。
- 日志表中的“提取单据编号”和“识别报文”始终为空，建议填充真实值或删除这两列。
- 「模拟数据」勾选框仅用于开发和演示阶段，业务稳定后建议移除该开关，全部走真实接口。
- 当前没有自动化测试，发票 LPN/Serial 拆分逻辑建议补充单元测试。
